# 자산 데이터를 서버에 두지 않는 이유

골고루를 만들면서 처음부터 정한 원칙이 하나 있습니다. **사용자의 자산 데이터는 앱 제공자 서버에 두지 않는다.** 계좌 잔고, 보유 종목, 가계부 기록 모두요. 기능을 만들 때마다 이 원칙 때문에 길을 돌아간 적이 많습니다.

## 그럼 데이터는 어디에

| 무엇 | 어디에 |
| --- | --- |
| 계좌 · 보유 종목 · 현금 · 목표 비중 | 기기 안의 앱 전용 영역. 아이폰 · 아이패드 · 맥은 본인 iCloud로 동기화 |
| 가계부 기록 | 기기 안. 아이폰 · 아이패드 · 맥은 본인 iCloud(CloudKit 개인 데이터베이스) |
| 안드로이드 기기 간 공유 | 켠 경우에만 본인 구글 드라이브의 파일. 앱이 만든 파일만 보는 `drive.file` 권한 |
| 짜보기 구성안 | 기기 안. 애플 기기는 본인 iCloud에 미러링 |

본인 iCloud · 구글 드라이브는 사용자 계정에 속한 공간이라 앱 제공자가 들여다볼 수 없습니다. 아이폰 · 아이패드 · 맥에서는 파일 보호 속성을 붙여, **기기가 잠긴 동안에는 앱도 읽을 수 없습니다.**

## 그래서 하지 않은 것들

- **회원가입 · 로그인이 없습니다.** 계정을 만들 이유가 없으니까요. 처음 열면 예시 자산으로 바로 둘러봅니다.
- **은행 · 카드사 연동이 없습니다.** 대신 증권사 화면이나 카드 내역을 캡처해 기기 안에서 읽습니다. 이미지는 보내지도 저장하지도 않습니다.
- **평가액 계산도 기기 안에서** 합니다. 달러 자산의 원화 환산도 앱이 받아 온 환율로 앱 안에서 합니다. 서버에는 자산 금액을 보내지 않습니다.

## 그래도 밖으로 나가는 것

전부 기기 안에서만 할 수는 없습니다. 밖으로 나가는 것을 숨기지 않고 적어 둡니다.

- 시세 · 뉴스를 받을 때의 **종목 심볼과 검색어**
- 나눔터에 직접 올린 조합의 **종목과 비중**(투자금 · 주수 · 평가액은 빼고)
- 남에게 보내는 공유 링크는 구성을 주소의 `#` 뒤에 싣습니다. 이 부분은 서버로 전송되지 않아 접속 기록에도 남지 않습니다.

## 왜 이렇게까지

자산 데이터는 한 번 새면 되돌릴 수 없습니다. 제가 서버를 아무리 잘 지켜도, 서버에 없는 데이터가 가장 안전합니다. 저 혼자 만드는 앱이라 더 그렇습니다. 지킬 게 적을수록 실수할 곳도 적으니까요.
